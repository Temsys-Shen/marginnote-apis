卡组技术上是 Topic（与学习集同构），界面语义独立（首页不同 tab、标签分家）。**两端点各管一种，id 不通用**（传错 422 `NOT_A_DECK`/404）。参数、Schema、多语言示例、Try-it 见各端点交互页（左侧 Decks 分组）。

## GET /decks（免 Max）

> [交互式](/docs/decks/get-decks)

- `{deckId,title,cardCount,lastModifiedAt}`。`cardCount` 仅复习卡本身（与库 `noteCount` 口径不同，对不上正常）。

## POST /decks（需 Max + confirm）

> [交互式](/docs/decks/post-decks)

- 回 `{deckId,isDeck}`，**须校验 `isDeck:true`**。

## GET /decks/\{id\}/cards（免 Max）

> [交互式](/docs/decks/get-decks-id-cards)

- `sourceAlive:false` = 原卡已删/隐藏（卡在，背面空白，如实告知）。

## POST /decks/\{id\}/cards（需 Max + confirm，≤50/次）

> [交互式](/docs/decks/post-decks-id-cards)

- 一张复习卡 = 正面 + 背面（`sourceNoteId` 原卡，不复制；必填，否则背面空白）。正面三选一互斥：`questionContentId`（精确选 parts 内容，图片挖空走此，勿自传内部 index）/ `question`（自定义，`{{挖空}}`）/ 都不给（自动出题，复合卡勿依赖）。
- 幂等：同源卡重复加为更新并重排到期；跨组各建。组员 id 归一宿主（以 `resolvedNoteId` 为准）。
- 删单卡用 `POST /notes/delete`（单向联动：删复习卡不影响源卡；删源卡级联删复习卡）。删整组用 `POST /study-sets/{deckId}/delete`（`keepHighlights:false` 才真干净）。

## POST /decks/\{id\}/open（免 Max，无 confirm）

> [交互式](/docs/decks/post-decks-id-open)

- 打开卡组。异步，事后 `/context` 对账。抢屏，仅用户要求时用。
